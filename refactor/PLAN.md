用户已确定：**先实现 Windows，所有依赖使用最新稳定版，先开发基础功能**。本节优先于下文原有的三平台同步推进门槛。

- 基础功能范围：文本采集、SQLite 历史、精确内容去重、搜索、复制回剪贴板、删除、置顶、暂停/恢复。
- 首批暂缓的全局唤出快捷键与托盘现已在 Windows 基础版实现；旧版数据库支持显式只读导入，自动迁移仍未实现。HTML/RTF、PNG 图片和普通文件路径基础能力已接入；经快捷键唤出后可受控向原窗口发送粘贴快捷键，但跨应用最终效果仍待验收。虚拟文件保真、其他图片格式保真、同步、翻译和安装更新仍未实现。
- Windows MVP 使用独立用户数据目录；保留旧 Tauri 入口。
- 新 workspace 的直接依赖按 crates.io 最新非撤回稳定版选取，提交 Cargo.lock；每批开发开始检查更新并做回归，不使用浮动 Git 主分支。
- 按后续“继续完善 GPUI 重构”的指示，接入稳定版 gpui-kit 0.6.2，并保留其上游锁定的间接依赖。Windows 依赖链包含 ropey 2.0.0-beta.1，属于明确记录的框架例外，不能宣称整个依赖树均为稳定版；详见 [技术决策](decisions/0001-windows-gpui.md)。
- Windows 主窗口已补充全文预览：按需读取、Space 打开、Esc 返回、复制全文及过期响应保护；文本、网址与 HTML/RTF 可在预览中编辑，修改后的富文本明确转为纯文本。
- Windows 主界面已增加收藏/取消收藏和收藏视图，与搜索、分页及请求代次校验联动。
- Windows 主界面已接入跟随系统/浅色/深色主题，复用 SQLite 设置存储并支持重启恢复；系统动态通知已接入，真实系统切换验收待完成。
- Windows 历史卡片可拖拽插入式排序，收藏独立排序；共用间距、控件高度与动效规则，并以数据库事务保护顺序。
- Windows 主窗口已接入托盘：关闭后继续运行、托盘恢复和显式退出；托盘失败时保留正常关闭。
- Windows 主窗口可在 `Ctrl+Shift+V`、`Alt+C`、`Ctrl+Alt+V` 与关闭之间切换全局唤出快捷键：关闭到托盘后可恢复并聚焦，注册冲突时保留原快捷键与托盘入口；设置独立于旧版 `global_shortcut`。
- Windows 旧数据可显式导入空 GPUI 目录，保留数据库中的全部记录和元数据；当前 UI 可浏览、新建、重命名及删除自定义分组，将已有记录移入或移出分组，组内搜索与排序独立。GPUI 删除分组会在确认后将组内记录移到默认分组，区别于旧版的级联删除。外部图片保留原路径，图片文件缺失时不能预览/复制；文件源缺失时仍可查看路径，但不能复制。
- Windows 同一数据目录重复启动会唤回已有窗口，独立数据目录仍允许并行实例；唤出事件与实例锁共用目录身份。
- Windows 暂停采集状态已持久化，在监听启动前恢复；保存失败不会切换内存中的采集状态。
- Windows PNG 图片现可从剪贴板采集、持久化、搜索列表中展示缩略图、预览与复制；文本、网址、富文本、图片和文件卡片现共用预览底板、操作区、行高与拖拽浮层，目标插入线区分可放置和不可放置，动画统一并遵从减少动态效果设置。文本、富文本、图片与文件路径已经通过非交互式窗口站中的真实系统剪贴板往返验证。
- Windows 普通文件/文件夹路径现可采集、预览与复制；不备份文件内容，源路径失效时提示错误。文件卡片同样复用统一布局、拖拽与动效；虚拟文件及伴生格式未接入。
- Windows HTML 与 RTF 按文本格式优先于位图预览采集，RTF 原始字节以旧版兼容的 Base64 形式保存；预览仅显示纯文本表示。默认写回尝试保留纯文本、HTML、RTF 中可用的格式并读回检查；另有明确的纯文本复制入口，只写入已有文本表示。真实跨应用效果尚未验收。
- Windows GPUI 历史现可导出 v2 ZIP 备份，包含 SQLite 在线快照及引用的可读取图片、图标与暂存文件；`--import-backup` 可恢复 v1/v2 备份到显式指定的空数据目录，并在暂存前检查原始 ZIP 中央目录，拒绝重复条目、超量文件与超量展开大小。`--import-legacy-backup` 可将旧版 Tauri ZIP 导入空目录，升级数据库并重建归档媒体路径；旧版暂存文件在原文件消失时可作为普通文件路径复制的回退。默认备份仅导出 GPUI 使用的三项设置，两种 ZIP 导入均拒绝覆盖现有数据。GPUI 新采集的普通文件路径仍不备份文件内容，虚拟文件完整保真仍待实现。
- Windows 主界面可确认清理当前分组历史：仅删除未置顶且未收藏记录，搜索与收藏筛选不改变清理范围；已删除记录关联的本地图片按引用清理。清理请求校验列表代次，避免切组后的旧操作误删。
- Windows 主界面还可逐条勾选或全选已加载记录，确认后批量删除；此操作明确包含选中的置顶和收藏项，按当前分组与列表代次校验，在单个 SQLite 事务内删除并清理无引用媒体。搜索、分组或收藏视图切换会清空选择。
- 本轮详细状态和运行方法记录于 [Windows 基础版](WINDOWS_MVP.md)。

## 1. 目标与边界

### 1.1 最终结果

1. 用 Rust 原生 GPUI 界面替代 React、WebView 与 Tauri 应用壳。
2. 保留剪贴板历史、搜索、分组、收藏、编辑、预览、导入导出、同步与翻译等已有产品能力。
3. 三平台共用业务逻辑，以平台适配层处理剪贴板、快捷键、窗口、系统集成与权限。
4. 已有 Windows 用户的数据可验证地迁移，迁移失败可继续使用旧版。
5. 平台限制在界面中明确表达，不把不可用操作显示为成功。
6. 提供原生平台构建、真实桌面验收、可恢复升级和持续集成。

### 1.2 实施原则

- 先验证平台关键路径，再迁移全部界面；不以“窗口能打开”证明剪贴板应用可用。
- 渐进提取已有 Rust 代码，保留旧入口作为对照，避免重写数据库和同步协议。
- 优先打通文本采集、搜索与粘贴，再扩展富文本和文件保真。
- 同一时刻只允许一个进程负责系统剪贴板采集；开发版与正式版使用隔离数据目录。
- 平台不支持时提供明确降级。Windows 专属功能无需在其他平台伪造对应实现。
- 只在真实边界引入接口；不预建插件宿主、脚本引擎或通用依赖注入框架。
- 文档中的库、版本与系统最低要求在 S0 锁定；不随上游主分支自动漂移。

### 1.3 完成层级

| 层级 | 定义 |
|---|---|
| 技术原型 | 在指定系统打开窗口、显示文本并验证平台关键能力；不能作为可发布版本 |
| MVP | 在声明支持的环境完成文本采集、持久化、搜索、复制；自动粘贴可明确降级 |
| Beta | 数据迁移通过、主要功能完成、三平台有实际运行证据及已知限制清单 |
| 正式替换 | 功能矩阵逐项完成或明确记录平台限制，发布与回退验证完成，才移除旧技术栈 |

三平台是最终目标。某个平台原型失败时，记录阻塞并继续独立工作，不将它静默从目标中删除。缩小正式支持范围或删除已有功能需要单独记录产品决策。

2026-09-18 已有检查结果：ESLint、TypeScript 通过；Rust 库测试 176 项通过；前端 229 项中 228 项通过，1 项耗时阈值失败，单独复跑性能文件 28 项全部通过。这是旧版基线，不是 GPUI 测试结果。

迁移必须覆盖的既有风险：

- release `panic = "abort"` 与 worker 的 `catch_unwind` 恢复意图冲突。

- 采集队列合并仅保留最后事件，可能丢弃不同复制操作。
- 更新下载的文件名、来源与安装包真实性校验需完善。
- 浏览器 E2E 不覆盖原生剪贴板、焦点与系统快捷键。

## 3. 依赖与平台可行性

### 3.1 gpui-kit 候选

Windows 首批实现已采用 [longbridge/gpui-kit](https://github.com/longbridge/gpui-kit) 0.6.2；依赖范围与平台边界见 [技术决策](decisions/0001-windows-gpui.md)。其他平台可行性仍待验证。

截至本次查阅，[官方安装文档](https://gpui-kit.com/docs/installation/) 给出 `gpui-kit = "0.6"` 示例，由 Kit 配套 GPUI 依赖，并列出 macOS 15+、Windows 10+ 和 Linux 开发环境。它们只是当前文档信息，不等于本项目最终最低运行要求；S0 必须结合锁定版本、实际构建与运行结果确认。

S0 输出精确版本或 Git revision、Rust toolchain、Cargo.lock、系统依赖、许可证与分发资源清单。初期不引入 JavaScript 扩展宿主。

### 3.2 候选平台矩阵

以下是验证目标，不是已经支持的承诺。

| 环境 | 初始验证架构 | 必须验证 | 特殊处理 |
|---|---|---|---|
| Windows 10/11 | x86_64；随后验证 ARM64 | CF_UNICODETEXT、图片、文件、全局唤出、目标窗口粘贴 | Win+V、管理员目标、DPI、DWM 特效单独验收 |
| macOS | Apple Silicon；Intel 单独验证 | Pasteboard、Cmd+V、菜单栏、权限、输入法 | 最低系统版本由锁定依赖实测确定；权限拒绝须可恢复 |
| Linux X11 | x86_64；ARM64 后续验证 | CLIPBOARD 读写与所有权、快捷键、目标窗口输入、托盘 | PRIMARY 与 CLIPBOARD 分开，默认仅处理 CLIPBOARD |
| Linux Wayland | x86_64；按桌面环境记录 | 后台采集、可用协议、Portal、快捷键、剪贴板写入 | GNOME、KDE Plasma、一个 wlroots 环境分别测试，不推定通用能力 |

跨编译成功只能标记“构建通过”。无真机或桌面会话证据的目标不得标记为“已验收”。

### 3.3 平台能力契约

每项能力返回 `Available`、`NeedsPermission`、`Unavailable(reason)` 或临时失败状态；授权与桌面会话变化后允许刷新。

| 能力 | 通用行为 | 不可用时行为 |
|---|---|---|
| 后台监听 | 捕获实际可读取的格式，保存后通知 UI | 明示无法自动记录，保留历史浏览与显式导入剪贴板；不宣称完整剪贴板管理支持 |
| 全局快捷键 | 注册、冲突检测、解绑、配置更新 | 提供应用入口；托盘存在时可从托盘打开 |
| 自动粘贴 | 写入成功后恢复目标，再注入正确平台快捷键 | 保留“复制到剪贴板”，提示用户手动粘贴 |
| 不抢焦点窗口 | 能力允许时启用，搜索编辑可明确切换输入焦点 | 使用普通窗口，保证可访问性和文字输入 |
| 来源应用识别 | 提供可获得的名称、图标与标识 | 展示未知来源，不把未知当成可信来源 |
| 来源过滤 | 白名单、黑名单规则可追踪 | 白名单下未知来源默认不采集；其他模式明确未知来源策略 |
| 托盘/菜单栏 | 支持时后台常驻 | 保留可发现的打开与退出入口，避免窗口隐藏后无法找回 |
| 系统特效 | 按平台支持启用 | 实色背景；不影响基本可用性 |

Wayland 的全局快捷键、后台读取和输入注入是不同能力。不得以一个 Portal 可用推断全部可用。[GlobalShortcuts 文档](https://flatpak.github.io/xdg-desktop-portal/docs/doc-org.freedesktop.portal.GlobalShortcuts.html) 描述快捷键接口；[Clipboard Portal 文档](https://flatpak.github.io/xdg-desktop-portal/docs/doc-org.freedesktop.portal.Clipboard.html) 说明剪贴板访问依附于其他 Portal 会话，并受会话条件限制，不能直接视为通用后台监听方案。

## 4. 目标代码结构与依赖方向

以下目录是 S1 的目标，本次规划不创建空实现。

```text
Cargo.toml                     # 新 Rust workspace；S1 处理旧 crate 的归属
crates/
  clipboard-core/              # 模型、仓储、去重、配置、业务用例、同步/翻译服务
  clipboard-platform/          # 能力接口与 Windows/macOS/Linux 实现
  clipboard-gpui/              # 原生应用入口、视图、状态、资源与交互
src-tauri/                     # 过渡期旧壳，通过共享核心工作
src/                          # 过渡期旧 UI，验收后再移除
clipboard-rs/                 # 暂保留本地分叉，S0/S3 决定长期处理
refactor/
  README.md
  PLAN.md
  decisions/                  # 后续记录技术决策及否决理由
  evidence/                   # 后续记录平台验证与性能摘要，不提交个人剪贴板数据
```

依赖方向：`clipboard-gpui -> clipboard-core`；`clipboard-gpui -> clipboard-platform -> clipboard-core`。平台接口及中立模型位于 core，core 不依赖 GPUI、Tauri 或具体系统 API。UI 负责组装实现；网络服务不直接持有窗口。

初始只保留三个 crate；模块长大后再决定是否拆出存储或同步 crate。与“一次性重写全部代码”相比，渐进提取能保留数据库和格式行为对照，并让每一步可回退。

### 4.1 边界接口

- `ClipboardBackend`：读写多格式快照、监听生命周期、系统序号/来源提示。
- `DesktopIntegration`：能力查询、快捷键、托盘、自启、通知、打开文件与目录。
- `PasteController`：目标捕获、焦点恢复、输入注入；与“只写剪贴板”分离。
- `AppEventSink`：类型化业务事件，替代 Tauri 字符串事件。
- `AppPaths`、`SecretStore`：数据位置与敏感凭据；具体平台实现可替换。

这些是职责划分，不要求为每个名称创建独立 trait。先以实际调用方和测试替身确定最小接口。

### 4.2 状态与线程

- 数据库是持久化事实源，UI 是查询视图；配置由统一服务管理，多窗口不各自保存冲突副本。
- GPUI 主线程只更新实体与渲染；数据库、网络、图像处理在受控后台执行。
- 搜索、筛选、预览分别带请求代次或取消标识；异步结果回到 UI 时重新确认上下文。
- 采集使用有界队列，记录溢出与处理延迟；仅合并能证明属于同一复制事务的事件。
- 自身写入抑制采用 RAII/作用域机制；用户暂停与内部抑制独立，错误路径确保释放。
- 顺序：完成媒体落盘与数据库提交后再发成功事件；失败需清理或留可恢复状态。
- 关闭时注销快捷键、停止监听、取消任务、关闭数据库；重启/休眠恢复可重复执行。
- 若需要 panic 隔离，发布配置必须允许 unwind，并用发布模式验证；不能把 panic 当普通错误处理。

## 6. 数据兼容与安全迁移

### 6.1 存储策略

- 新安装使用平台标准用户数据目录，具体应用标识和目录在 S0 固定。
- Windows 保留显式便携模式与自定义目录；其他平台是否提供便携模式在打包阶段记录。
- 初期沿用现有 SQLite schema、去重规则与导出格式，避免 UI 重构同时引入不必要的数据格式变化。
- Windows 原始格式载荷以可选平台扩展保存；跨平台统一字段提供文本、图片、URI/文件等可用表示。
- 本机绝对路径不能代表另一台设备上的文件；跨平台同步必须依靠媒体映射与本地重建。

### 6.2 迁移步骤

1. 检测旧 `config.json`、默认/自定义数据库及媒体目录，让用户选择确认的数据源。
2. 检查旧进程退出或获得一致性快照；禁止直接复制正在写入的 WAL 数据库主文件作为完整备份。
3. 使用 SQLite backup 或已验证的一致性方案，复制数据库与引用媒体到新临时目录。
4. 校验完整性、条目数、分组/收藏/排序、引用文件与抽样内容；记录缺失媒体，不误报完全成功。
5. 在副本上运行迁移；对路径、平台载荷与未知设置做兼容转换。
6. 验证成功后切换新版本配置；同文件系统内使用原子替换，跨盘迁移采用复制、校验、切换。
7. 保留原目录和迁移报告；失败清理仅限本次临时文件，旧版仍能打开原数据。
8. 提供“返回旧版本”的流程：旧版继续使用原副本；新版本新增数据需兼容导出后再导入，不能直接用旧版打开升级后的新库。

凭据迁移到平台安全存储，先验证写入与读取成功再移除旧明文；Linux 安全存储不可用时要求显式选择会话凭据或后续方案，不静默落盘。导出默认排除密码和 token，同步/日志不记录敏感正文。以上为拟实施要求，不能宣称旧版已满足。

## 8. 验证体系与性能预算

### 8.1 分层验证

| 层次 | 验证内容 | 注意事项 |
|---|---|---|
| 纯逻辑单测 | 去重、排序、查询条件、路径映射、配置、错误转换 | 不依赖系统剪贴板 |
| 数据集成测试 | 旧 schema、备份、导入、事务、媒体清理、失败恢复 | 只使用临时目录与合成数据 |
| 平台契约测试 | 能力状态、抑制释放、监听退出、格式转换 | mock 验证调用契约，不能替代原生测试 |
| GPUI UI 测试 | 操作状态、筛选竞态、多窗口同步、键盘事件 | 采用锁定 Kit 版本实际可用的测试机制 |
| 原生桌面验收 | 系统复制/粘贴、输入法、热键、托盘、授权、焦点 | Windows/macOS/X11/各 Wayland 环境分别留证据 |
| 发布验证 | 签名、安装、升级、迁移、卸载、回退 | 用打包后的 release 制品执行 |

代表性数据：空库、一万条混合历史、十万条压力库、超长中英文本、emoji、混合换行、二进制 RTF、HTML、透明图片、失效文件、中文/空格路径与跨平台媒体。不得提交真实个人剪贴板数据。

关键原生场景：浏览器、纯文本编辑器、办公应用、文件管理器；快速连续复制不同内容；同内容不同格式；目标窗口关闭；管理员/普通窗口切换；权限拒绝与撤销；显示器拔插；系统重启与唤醒。

### 8.2 暂定性能目标

以下为工程目标，S0 测量旧版及原型后固定测试硬件、数据集和阈值。调整必须记录原因，不以删除失败项方式达标。

| 指标 | 暂定目标与测量口径 |
|---|---|
| 文本采集可见延迟 | 常规文本从系统复制到列表可见 p95 ≤ 200ms，不含权限交互 |
| 一万条搜索 | 从提交查询到结果可交互 p95 ≤ 150ms，防抖等待单独记录 |
| 虚拟列表滚动 | 参考 60Hz 设备主线程帧耗时 p95 ≤ 16.7ms；图片首次解码单独统计 |
| 冷启动 | 基准机器至主窗口可交互 ≤ 2 秒；首次字体/着色器缓存另报 |
| 常驻开销 | 隐藏窗口无忙循环；空闲 CPU 与 RSS 对照旧版记录，不先承诺固定内存值 |
| 稳定性 | 8 小时负载后内存/线程/句柄无持续无界增长；采集失败可诊断 |

性能基准使用 release、固定数据、预热与多轮采样，独立运行；普通功能 CI 不依赖单次极窄墙钟阈值。

## 9. 风险与处置

| 风险 | 发现信号 | 处置 |
|---|---|---|
| Kit/API/系统要求变动 | 锁定版本与示例不一致、某平台不能启动 | S0 固定依赖；升级独立验证；必要时向上游提供最小复现 |
| Wayland 缺少必要能力 | 后台监听或输入注入不可用 | 按桌面环境记录，提供明确降级；不承诺全桌面等价 |
| 原生焦点与 IME 冲突 | 搜索不能输入、粘贴到错误窗口 | 把编辑焦点与粘贴目标分开，原生端到端测试优先 |
| 旧数据损坏 | 引用丢失、迁移中断、版本回退失败 | 副本迁移、校验、保留原目录、明确恢复路径 |
| 格式损失 | Office/文件管理器往返差异 | 保留原始可选载荷，统一跨平台表示，增加样本回归 |
| 范围持续扩大 | UI 未完成就引入新协议/插件引擎 | 保持当前功能映射；新增需求独立记录 |
| CI 编译通过但用户不可用 | 托盘、GPU、权限或桌面环境失败 | 打包后的原生会话验收，明确支持清单 |
| 更新或凭据风险 | 下载路径逃逸、无签名安装、日志泄密 | 更新与凭据边界独立测试，发布前阻断 |

## 10. 执行与记录规范

- 按阶段交付可运行增量；提交范围优先按“提取核心”“平台后端”“UI 用例”划分。
- 每个任务记录输入、修改模块、验证命令、结果、未覆盖平台与剩余风险。

- 未具备的硬件、桌面会话、签名凭据列为具体阻塞；不将未运行测试写成通过。
- S0 结束后再按实际原型和可用测试资源估算工期；本文不提供未经验证的日期承诺。
