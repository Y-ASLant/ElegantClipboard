# Windows HTML/RTF 接入（2026-09-19）

- 采集顺序改为文件 → HTML/RTF/纯文本 → 图片。Word 等应用附带位图预览时，文本类内容不会先被归为图片；富文本超过 1 MiB 时若有纯文本就按纯文本保存。RTF 原始字节沿用旧版 `b64:` 存储约定，避免 `\bin` 数据经 UTF-8 有损转换。
- HTML 与 RTF 沿用旧版内容哈希规则。RTF 在 ASCII 可安全规范化时忽略易变的 `rsid` 字段；非 ASCII/二进制原样参与哈希，避免旧实现的字符索引切片问题。新增直接依赖 [base64 0.23.1](https://docs.rs/crate/base64/0.23.1)，为查阅时的最新稳定版。
- 富文本卡片复用现有 160 px 行、拖拽手柄、按钮区和 160 ms 动效。预览显示纯文本表示，复制时尝试一次写回可用的纯文本、HTML 与 RTF，并读回确认；若只有纯文本写回成功，状态明确报告降级。旧版无效/有损 RTF 不作为可写回的 RTF 格式。
- 核心测试覆盖 HTML 与二进制 RTF 持久化、去重、旧版哈希语义、边界和混排排序；Windows 工作线程测试覆盖采集到数据库与预览。全工作区 119 项测试、严格 Clippy、格式检查、Windows debug/release 构建及 release 窗口冒烟通过。
- 使用 `target/qa/rich-ui` 隔离目录的合成 HTML/RTF 记录，以 `--no-monitor` 启动真实 GPUI 窗口。截图确认两类卡片和纯文本预览；真实鼠标将 HTML 卡片拖到 RTF 卡片下半区后，SQLite 顺序变为 RTF `sort_order=2`、HTML `sort_order=1`。截图留在忽略目录，未提交。
- 未读写真实系统剪贴板；因此不能据此宣称 Word、浏览器或办公应用之间的格式往返已通过。HTML 不在应用内执行，窗口只显示其纯文本表示。
