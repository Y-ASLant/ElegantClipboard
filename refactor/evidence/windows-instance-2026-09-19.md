# Windows 重复启动唤出验证

- 启动实例按规范化数据目录计算具名 Windows 事件名，持有实例锁与事件监听线程。第二个进程检测到已有事件后发出唤出信号，已有 GPUI 窗口通过应用事件恢复并聚焦；第二个进程正常退出。实例锁与信号在退出时释放。
- 若第二次启动恰好发生在第一个进程取得锁、尚未创建事件之间，锁冲突路径会短暂重试唤出信号。其他启动错误仍原样返回。
- 单测验证同一数据目录可以收到唤出事件，另一个目录不会收到，服务关闭后事件消失。
- Windows 原生跨进程测试使用 `--no-monitor` 和 `target/qa` 隔离目录：第一个窗口关闭后不可见但进程存活；第二次启动同目录退出码 0，并重新显示第一个窗口；另一个目录启动独立窗口并保持运行。测试结束清理两个隔离进程。
- 首轮 release 冒烟曾有 1 次超过 20 秒未退出，另 4 次复跑成功。检查发现冒烟定时器未设置显式退出标记，可能与关闭到托盘拦截冲突；补齐该标记后重新构建 release，在 5 个新隔离目录连续运行冒烟均于超时阈值 12 秒内以 0 退出。尚未独立证明首轮超时的唯一原因。
- `cargo test --workspace --locked --quiet`：101 项通过；fmt、Clippy `-D warnings`、Windows debug/release 构建通过。
