# Windows 首批 GPUI 实现

日期：2026-09-18。范围：Windows 文本历史基础版。

## 栈与依赖

- 使用 crates.io 的 `gpui-kit 0.6.2`，与其匹配的 GPUI crate 由 Kit 引入，应用不再自行指定第二套 GPUI。
- 直接依赖均已在本轮重新查询最新稳定版；Cargo.lock 固定实际解析结果。
- 用户在依赖差异已说明后要求继续完善 GPUI，本轮据此继续使用 Kit 的官方依赖链。Windows 链中的 `ropey 2.0.0-beta.1` 是间接例外，未私自将其替换成不兼容的 ropey 1.x。
- `gpui-pre-*` 是上游包名，本轮使用的版本号为 0.3.5；包名包含 pre 与版本号带 beta 后缀是两种不同情况。
- 非 Windows 后端未启用，不以依赖库的跨平台声明代替本项目运行验证。

核验命令：

```powershell
cargo tree -p elegant-clipboard-gpui --target x86_64-pc-windows-msvc -i ropey
```

## 界面与生命周期

使用一个普通、有系统标题栏的窗口。正文沿用紧凑文本历史的交互：上方搜索、虚拟列表、每条记录的置顶/删除/复制操作、底部状态反馈。现阶段保留系统任务栏入口，关闭窗口即退出，不实现隐藏后常驻或托盘。

Windows 正文使用 Microsoft YaHei UI，颜色跟随 Kit 当前主题；选中行使用主题强调边框。采用固定高度虚拟行，预览最多两行，复制始终由后端读取完整正文。

后台服务通过有界事件通道更新 UI；UI 不轮询数据库。搜索等待 150ms，输入变化立刻增加请求代次，旧查询结果不能回填新视图。暂停状态以后台确认事件为准。

## 本轮保留的边界

- 无自动粘贴到目标窗口；复制成功后用户切换应用按 Ctrl+V。
- 无自动迁移旧版数据，默认使用独立 GPUI 目录。
- 无全局快捷键、托盘、图片/文件/富文本卡片、同步和翻译。
- `--no-monitor` 仅禁用采集，用户点击“复制”仍会主动写剪贴板。
- 冒烟测试必须指定独立目录，自动禁用采集并在短暂运行后退出。

参考：[Kit 官方入门](https://gpui-kit.com/docs/getting-started/)、本地锁文件与已下载的 gpui-kit/gpui-base 0.6.2 源码。
