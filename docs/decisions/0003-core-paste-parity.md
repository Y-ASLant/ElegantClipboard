# 0003 基础功能补齐：恢复剪贴板、去重策略、文本转换、按格式粘贴、条目备注

日期：2026-10-26　状态：已实现

## 背景

功能盘点（2026-10）确认了复制→捕获→存→搜→贴→还原链路上的五处用户可直接感知的缺口。本决策固定它们的形态与默认值，避免实现时再次发散。

## 决策

### 1. 粘贴后恢复用户原剪贴板（默认关闭）

- 受控粘贴（CopyForPaste）写回条目前，worker 若开启恢复则先读取当前剪贴板完整快照（主内容 + 额外原生格式）暂存在 worker 内存；粘贴快捷键发送成功后由 UI 发 `RestoreStashedClipboard` 写回快照并抑制自捕获。
- 默认**关闭**：写回快照与目标应用读取剪贴板存在时序竞争（SendInput 异步），开启恢复会牺牲"粘贴后再手动 Ctrl+V 一次"的场景。关闭时保持现状（剪贴板保留所贴条目）。
- 快照不可得（隐私标记格式、读取失败）时静默放弃恢复，不影响粘贴本身。隐私标记内容同样参与快照——恢复不是入库，不违背隐私标记的本意；但 `ExcludeClipboardContentFromMonitorProcessing` 命中时主内容读不到，即无快照可恢复。
- 快照归属到单次 `request_id` 与写后剪贴板序列，恢复命令必须匹配两者；当前剪贴板已被其他应用改写时拒绝恢复。Windows 在打开剪贴板的同一会话内核对序列并恢复，Unix 写前核对当前序列。
- 失败、取消、新复制或合并都会丢弃旧快照；成功关闭恢复设置也清除快照。未创建快照的纯文本、转换、单格式及合并投递不能取用其他请求的快照。

### 2. 去重策略可切换（默认 move_to_top）

- 两档：`move_to_top`（现状：同哈希移顶不新建）与 `always_new`（同哈希也各存一条，靠时间线保留上下文）。
- 存储为 GPUI 偏好 `gpui_dedup_strategy`；schema 种子里的 `dedup_strategy`/`text_dedup_mode` 行无消费者，保持原样不读。
- `always_new` 跳过 `touch_by_hash` 与同文合并（两者都是去重形态）；哈希索引自迁移 8 起已非唯一，直接插入即可。
- 设置页放在"数据"页保留策略旁，同屏可见。

### 3. 文本转换复制/粘贴

- `TextTransform`：`Trim`（去首尾空白）、`RemoveLineBreaks`（换行折叠为空格）、`Uppercase`、`Lowercase`。core 纯函数，无平台依赖。
- 作为复制变体接入既有 `CopyMode`：菜单提供"复制为…"与"粘贴为…"（ForPaste 变体），与纯文本/路径变体同构。大小写转换用 Unicode 大小写映射（`to_uppercase`/`to_lowercase`），不做 Turkey/I18n 细化。

### 4. 按格式粘贴（富文本条目）

- 富文本条目的行菜单增加子菜单"按格式粘贴"：纯文本（既有）、HTML、RTF 三个目标格式。
- 复制模式新增 `Html`/`Rtf`：只写所选单一格式；条目缺少该格式时 worker 报错提示，不做降级（降级交给用户重选，避免"以为贴了富文本实际是纯文本"）。
- 列表行不含富文本内容列，子菜单不预判禁用态，由 worker 校验。

### 5. 条目备注（note）

- `clipboard_items` 新增 `note TEXT` 列（迁移 12），NULL = 无备注；上限 2000 字符，超限拒绝。
- 备注参与关键词搜索（与 text_content/file_paths 同条件 LIKE）；搜索命中只来自内容时预览逻辑不变。
- 备注从记录右键菜单进入独立编辑对话框，保存走 `SetNote` 命令并校验记录仍存在；已移除原完整预览页入口。列表卡片不显示备注，避免行高变化。

## 后果

- 备份 v2 是数据库整体快照，`note` 列随库走，无需改备份格式；旧版 Tauri 导入不受影响（显式列清单）。
- `always_new` 下快速粘贴槽位与列表顺序仍按 sort_order，行为一致。
- 恢复剪贴板开启时，粘贴按键已发送仅证明输入事件已投递，不能证明目标已读取内容；恢复仍有目标异步读取的限制，因此默认关闭。写回快照的序列号进入 ignored_sequence，不会被录进历史。
