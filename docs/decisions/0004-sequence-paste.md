# 0004 序列粘贴（粘贴队列）

日期：2026-10-26　状态：已实现

## 背景

Ditto 的 stack paste（序列粘贴）是其粘贴端最大的独有能力：多选记录后，目标应用里按一次推进键送出第一条，再按一次送出第二条，逐条推进直至队列耗尽。本决策固定 ElegantClipboard 的实现形态。

## 决策

### 1. 编排放在 UI 层，复用受控粘贴链路

- 多选进入序列模式：批量操作栏新增「序列粘贴」按钮（≥2 条时可用，队列按列表顺序排列）。序列模式只是把多个 `CopyForPaste(id, request_id)` 按 request 关联逐个执行：每条等待 `Event::Copied{request_id}` → `return_to_paste_target` 发送粘贴键 → 粘贴送达确认后推进下一条。
- 队列耗尽或中途失败即结束序列并回到批量选择态；删除记录、复制、窗口隐藏、列表刷新等打断队列时序列自动取消。
- 不在 worker 侧做队列状态机：worker 保持无状态命令处理，跨条目的推进逻辑（等待、取消）都在 UI 单线程完成，与现有 `paste_pending`/`batch_paste_pending` 的请求关联模式一致。
- 无有效目标窗口时不可进入：序列粘贴是「回贴」能力，需要 `paste_target`（从目标应用按全局快捷键唤出后保留的原窗口）。无目标时按钮禁用并提示。

### 2. 推进键：全局热键 `Ctrl+Shift+G`（默认，可录制）

- 序列激活期间主热键保持原义（唤出/隐藏面板，隐藏即取消序列）；推进是独立的全局热键 `Ctrl+Shift+G`，在目标应用里按键即送出队列中的下一条。与主热键、快速粘贴槽位做冲突校验（复用 `validate_paste_shortcuts` 的互斥集合思路）。
- 偏好 `gpui_sequence_paste_hotkey`，设置页「快捷键 → 快速粘贴」区块提供录制/停用；停用后批量操作栏仍可进入序列模式（用面板内 Enter 逐条推进的替代路径不做——推进键停用时按钮禁用并提示），默认开启。
- 热键线程仅在序列激活期间注册推进键？否——热键线程是无状态的，无法感知 UI 状态。推进键注册为常驻全局热键（与快速粘贴槽位同线程模式），未激活序列时按键仅忽略；这保证目标应用里随时可按，UI 收到事件后依据序列状态决定推进或忽略。

### 3. 推进语义与队列生命周期

- 进入序列：UI 记录 `(ids, target, index=0)`，立即隐藏窗口并发送第一条（复用 `paste_selected` 的完整校验）。
- 每次推进：等待修饰键释放（复用 `PendingPaste` 的等待逻辑）→ 粘贴送达 → index+1；队列耗尽后显示完成提示并退出序列。
- 中途按主热键唤出面板再选择其他记录会取消序列；Esc/点击外部隐藏窗口取消序列；序列进行中再次按推进键在等待阶段被忽略（`paste_pending` 忙）。
- `RestoreStashedClipboard`（决策 0003）在每条粘贴送达后照常执行：恢复的是"该条粘贴前"的剪贴板。

## 后果

- 快速粘贴槽位校验新增推进键互斥；推进键与主热键冲突时保存拒绝并回滚。
- 批量操作栏按钮数量增加一个；序列进行中批量栏显示剩余条数。
- 无新增数据库结构；队列仅存在于 UI 内存。
