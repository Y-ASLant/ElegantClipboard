# 待办复用主页拖拽与预览（2026-11-12）

## 原因与实现

待办原来只用 GPUI 的 `on_drag` 创建 `TodoDrag`，由主窗口绘制拖拽预览；历史卡片则通过 `CardDragSession` 接管指针、原生坐标换算和透明预览浮窗。两条路径独立，待办没有使用主页的浮窗跟随、源卡片占位和拖动中让位逻辑。

本次将历史与待办接到同一个 `CardDrag` / `CardDragSession`。两种卡片共用原生指针采样、DPI 换算、抓取点偏移、预览窗口复用、松手提交、Escape 取消与结束清理。`DragPreview` 根据卡片类型渲染领域内容，外壳统一使用 `drag_visual::drag_card`。没有复制另一份原生窗口或轮询实现。

`DragMotionState::update` 改为接收领域 ID 迭代器，不再依赖历史记录数据库类型。待办复用主页的 `hover_target`、`offsets` 和 `visual::drag_yield`，按实测行高实时让位。历史以置顶状态划分排序分区，待办以完成状态划分排序分区。保存待办顺序时沿用已显示的位置，收到列表回执后清理拖拽动效，避免再次从旧顺序滑动。

待办列表实际滚动容器、官方滚动条与落点计算统一使用 `todo_scroll`。底部和顶部拖动滚动由两种列表共用的任务驱动。窗口外拖放载荷仍只由历史条目提供，待办移出窗口再松手结束本次排序；待办不会因 ID 与历史条目相同而取得历史载荷。
