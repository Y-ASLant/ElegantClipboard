# 普通文件仅保存路径（2026-10-27）

用户要求取消自动保存普通文件实体，并在 `v2.0.0-beta.8` 清理旧副本。本次实现针对受管 `staged` 文件副本，不删除截图、图片历史、图片回贴临时文件或原生格式 blob；保留此前默认数据目录迁移改动。

## 行为

- 文件采集、普通复制、路径复制、合并、预览、原生拖放与另存为全部只使用历史记录保存的原始路径。原件移动或删除后明确显示失效并拒绝相应复制，不再回退到文件副本。
- 移除普通文件副本的设置、服务命令和回执、偏好 getter/setter、暂存写入器、容量配置及恒假的恢复状态；旧设置键在清理时删除。没有保留隐藏开启入口。
- Service 在持有当前 profile 实例锁并开库后调用 `History::remove_file_copies(data_dir)`。先事务移除 `file_payload` 顶层 `staged` 字段，保留其余历史字段、原始文件列表、未知 legacy payload、备注、分组、收藏、排序、时间戳及其他设置，再只删除当前 `data_dir/staged` 受管目录。
- 路径删除不依据 payload 的任意路径。校验 profile 与数据库目录一致，不跟随数据目录/副本根的符号链接或 Windows 重解析点；嵌套链接不递归进入外部目标。支持旧版嵌套 hash 子目录以及孤儿副本一起清理。
- 数据库清理失败时回滚且不动副本文件；磁盘占用、权限等失败留下未完成部分，启动通知提示并下次重试。没有副本目录时不创建该目录。
- 导出只清理在线快照，不改源数据库和源资产；新 ZIP 不包含 `staged/` 文件。恢复旧 GPUI/旧 Tauri ZIP 时仍校验归档名称、重复项和大小限制，但跳过副本实体，导入数据库也剥离副本引用。原始来源库及其文件不因导入被清理。

## 验证

- 核心边界回归覆盖：所有历史元数据/未知 payload 保留、重复 staged 键清除、数据库事务失败回滚、非法 JSON 保留原数据、目标 profile 与外部路径隔离、Windows junction 与文件被占用后的重试、普通采集不创建副本，以及旧 schema 的清理兼容。
- 备份/导入回归覆盖：旧 GPUI ZIP 含副本时不解压、新导出不带副本且不改源、旧 Tauri ZIP 仍恢复图片/图标和原始文件路径、单库导入不删除原库和源副本。
- 平台启动回归覆盖：带旧嵌套副本的 profile 启动时清理实体与引用、保留备注收藏和原始文件，再采集文件不重建副本。
- 全工作区 `cargo check --workspace --all-targets --locked`、严格 Clippy、格式和模块行数检查通过；256 个 Rust 源码/测试/示例均不超过 500 行。
- `cargo test --workspace --locked`：404 项通过（core 218、platform 129、GPUI 57），2 项原有忽略。
- Linux x64 与 macOS ARM64 的 `clipboard-platform --lib` 实际 zigbuild 交叉编译通过；这不等同于原生桌面运行。
