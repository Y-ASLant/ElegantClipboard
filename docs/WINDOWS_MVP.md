# Windows 基础版

## 范围

Windows 是主要验收平台，macOS 与 Linux 实现同仓构建（能力差异与验证边界见根 README）。仓库使用单一根 Cargo workspace，包含 GPUI 应用、共享核心和各平台原生实现。

首批功能：文本采集、历史持久化、精确去重、搜索、复制、删除、置顶、暂停/恢复。后续已增加全局唤出快捷键、HTML/RTF、PNG 图片和普通文件路径的采集、历史、预览与复制，以及经全局快捷键唤出后返回原窗口的受控粘贴；虚拟文件保真仍待开发。

## 当前实现

- `crates/clipboard-core`：包含数据库 schema、迁移、仓储和去重源码，提供 UI 无关的文本、HTML/RTF、图片与文件路径历史用例；额外原生格式与内容寻址 blob 存储也属此层。
- `crates/clipboard-platform`：三平台剪贴板事件监听、全局快捷键、托盘与原生格式写回；独立 worker 串行处理历史操作；请求代次、实例锁、重复启动唤出、有界队列和关闭清理。
- `crates/clipboard-gpui`：原生主窗口、搜索、虚拟历史列表、复制/删除/置顶、暂停确认、加载更多、文本/富文本/图片预览与文件详情、收藏与收藏筛选、导入分组浏览、组内拖拽排序、系统托盘和错误反馈。

数据库与去重源码已经物理迁入 `clipboard-core`；核心不依赖桌面 UI 框架或 Windows API。

源码模块与维护边界见[工程文档](README.md)。所有 Rust 源码、示例和测试文件上限为 500 物理行，`scripts/check-source-size.ps1` 在 `just check` 与 GPUI CI 中强制检查；拆分按职责而不是编号或文本包含进行。

默认目录为 `%LOCALAPPDATA%\ElegantClipboard`，不再包含作者和框架名称。升级时兼容迁移之前的 `%LOCALAPPDATA%\ASLant\ElegantClipboard-GPUI\data`，修正受管附件和开机启动路径，迁移成功后清理旧目录及空的专属父目录；新旧目录都有数据时保留旧数据并提示，不覆盖或静默合并。不自动清理旧版安装目录或任意自定义数据目录；这类旧库仍可显式导入到空目录。自动测试使用临时目录、合成文本和仓库内 PNG 样本。

限制：单条文本最多 1 MiB，富文本的 HTML、RTF 原始字节与纯文本合计最多 1 MiB；图片最多 2500 万像素、编码 PNG 最多 50 MiB；文件路径列表最多 256 项或 1 MiB，仅保存原始路径，不复制普通文件实体；启动时移除旧的受管 `staged` 副本及引用，原件移动或删除后明确提示失效，截图像素和图片复制不受影响。保留策略默认数量 10000、天数 0；显式保存后按各分组限制未置顶且非收藏记录，0 表示关闭相应限制，首次启用或收紧限制需要确认，旧配置不自动扩大清理范围。空白文本不保存。重复的完全相同文本移动到顶部，文字和换行原样保存。队列满时报告采集失败，不把不同复制事件主动合并成最后一条。

2026-10-25 起的采集与存储扩展：监听线程在五类主格式之外用 `EnumClipboardFormats` 枚举全部原生格式（内置常量黑名单过滤 OLE/Shell/Chromium 内部格式、隐私标记与已由主采集表示的格式），逐条存入 `native_formats` 表（主键 item_id+format_name）；超过 64 KiB 的格式数据以内容寻址方式落盘 `blobs/<hash>`（zstd 压缩、pending→commit 两阶段），单格式 8 MiB、单次采集 32 MiB 上限，超限跳过并提示。复制历史记录时（Original 模式）额外格式随主格式写回剪贴板，富文本在单 guard 会话内 text→html→rtf→extras 顺序写入，纯文本路径以独立 NoClear 会话追加；图片 Original 复制改为单 guard 写 CF_HDROP（内容寻址 `image_tmp/<hash>.png`）+ CF_DIB（手工组 BITMAPINFOHEADER+自底向上 BGRA）+ PNG，可直接粘贴为图片文件，image_tmp 在 worker 启动时清扫（超过 24 小时或 64 个）。监听采集（deferred=true）先进 300ms 瞬时确认窗口：到期时序列号未变或被自身写回取代则入库，重读为空或内容不同则丢弃，重读失败顺延 250ms 最多 3 轮；测试与 smoke 注入 deferred=false 绕过窗口；开关 `gpui_transient_filter` 默认开启，在数据设置页切换。相同纯文本（text/url/html/rtf，默认分组）再次复制时合并进既有条目：补缺 html/rtf 列、仅 text 目标升级类型、byte_size 重算、置顶，并在 `content_hash_aliases` 记录别名；`touch_by_hash` 在默认分组作用域内解析别名。五个删除路径（单删/批删/清空当前组/清空全部/保留策略）在提交数据库行删除前收集 blob 引用与别名，提交后由 cleanup_media 回收无引用 blob 并用 purge_stale_aliases 兜底；GPUI 备份 v2 增加 blobs 资产类别与 missing_blobs 计数，恢复原样重放（文件名即内容哈希无需重映射）。HTML 条目的 `PreviewContent::Html`（优先 StartFragment 片段）在完整预览页与悬停浮窗用 gpui-kit `TextView::html` 渲染富排版（含本地图片；http(s) 远程图片不加载），列表卡片与搜索仍用纯文本，RTF 与缺 html_content 的旧数据回退纯文本，编辑路径不变。

当前悬停富文本预览已改为：`PreviewContent::Html` 的片段在显示入口经 `htmd 0.5.6` 转换为 Markdown，交给官方 `TextView::markdown` 渲染，避免 GPUI Kit 0.8.1 的 HTML 行内代码段落共享元素状态导致文字丢失。正文不再设480px等固定宽度上限：复用纯文本字形测量估算Markdown源文本的首选宽度，在每个预览实例内缓存，再按主窗口旁的可用空间收缩。源文本标记可能留出少量额外宽度，实际换行后的高度仍由官方TextView布局测量；显示与隐藏测量使用相同确定宽度，避免不定宽容器逐字换行。长文通过来源卡片上的 Ctrl＋滚轮滚动。数据库与复制/粘贴仍使用原始 HTML；复杂 CSS、HTML 专属布局不保真，转换失败明确显示错误。上段的 `TextView::html` 描述仅记录此前实现。

- 主窗口仅展示历史列表，不再提供“查看详情”、Space 整页预览或图片/文件内嵌预览页；完整内容通过独立悬停浮窗查看。双击文本类记录或右键“编辑”打开官方 Dialog，保存后保留记录 ID、分组与收藏状态并刷新搜索结果；修改富文本会转为纯文本，空内容保存会报错，Esc 取消不写入，保存中禁止关闭。右键“编辑备注”提供独立备注对话框。图片和普通文件仍可从右键“另存为”打开系统文件选择，默认沿用源文件名；后台只接受现存普通文件，拒绝文件夹、失效源、相对目标和原地覆盖。
- 单张图片文件在历史卡片、完整文件详情及文件悬浮浮窗中显示图片，保留文件名、原始路径和大小信息；多文件及不支持预览的记录继续显示文件详情或路径。卡片缩略图的外部文件元数据检查在独立后台线程执行，不阻塞列表绘制；同一批已加载记录不会在每次列表刷新时重复检查。仅预览确认存在、元数据可读且大小已知的 PNG/JPEG/GIF/WebP/BMP 文件；本地路径上限 50 MiB，UNC 路径上限 10 MiB，超限或图片解码失败时显示回退内容。受管备份副本仍只在完整文件详情和悬浮浮窗中预览，历史卡片继续显示原始路径。
- 文件卡片还会在后台检查所有原始路径。任一原始路径不存在时，列表标题显示红色“源文件已失效”；无法读取元数据或路径无效时显示“文件无法读取”。文件名也使用警示色，图片缩略图仅在单文件可读且大小合规时显示。该提示只描述原始来源；旧备份中的受管副本是否可用于复制，仍以完整文件详情和执行时的校验为准。检查结果按记录 ID 和路径内容缓存，记录离开当前列表或路径变化后重新检查；本地路径先完成，网络路径随后返回，避免网络检查拖延本地提示。
- 文件卡片使用警告、普通文件和文件夹图标区分失效、单文件、文件夹与多文件；图片文件符合预览限制时优先显示缩略图。超过图片预览上限的文件显示“图片过大”，保留普通文件图标和文件名。多文件卡片显示前 3 个文件名，更多项以省略号结尾；显示大小时使用后台读取的真实文件字节数，只有全部路径都是可读普通文件时才显示总量，文件夹或失效来源不再显示路径字符串的字节数。
- 点击条目“收藏 / 取消收藏”保存常用记录；分类栏可切换“全部 / 收藏 / 文本 / 其他”，其中“文本”包含 text、HTML、RTF，“其他”包含图片、文件和 URL。分类与分组独立组合，搜索、数量与加载更多均由后台按分组、分类和关键词交集查询，不会只筛选已加载记录；取消收藏不会删除记录。收藏状态持久化，启动默认显示全部。
- 分类标签与 GPUI Kit `Select` 分组下拉位于同一行，默认分组固定首位；选择自定义分组会切换其历史，搜索、数量和分页限定在当前分组，并保留当前分类高亮及过滤条件。Select 的“+ 新建分组”和“重命名”使用 GPUI Kit `Dialog` 填写分组名称，确认保存后关闭并刷新分组，失败时在对话框内保留输入和显示错误，保存期间禁止取消与重复提交；选中自定义分组时下拉还提供删除及可用的上移/下移操作。顺序保存到 SQLite，删除前显示名称和记录数，确认后将组内记录移到默认分组，保留收藏与原始内容。每张卡片的“分组”按钮仍可将记录移到其他组，保存后列表与数量刷新；新采集内容仍进入默认分组。隐藏分类栏时分组 Select 仍可使用。
- 拖动显示实测原尺寸完整卡片：背景完全不透明，文字与图片不整体淡化，不显示操作按钮或额外阴影；列表留同尺寸空白占位，不绘制插入线。其他卡片用 300ms ease-in-out 动画让位，连续换目标从当前视觉位置继续，遵从系统减少动态效果设置。指针停在列表边缘时滚动已加载记录；同一置顶分区内可排序，跨分区不改变置顶状态。历史顺序写入 SQLite，收藏列表维护独立顺序，保存期间保留预览位置。Esc 取消拖动；保存已提交但列表刷新失败时明确报告并解除操作锁定。
- 持续按住左键拖出主窗口，会转为 Windows OLE 复制拖放，透明置顶且不激活的卡片浮窗继续保持原尺寸与抓取点。文本使用完整 Unicode 正文，HTML/RTF 提供已存富格式，文件提供原路径或有效受管副本，图片提供文件及 DIB；不通过系统剪贴板中转，不提供移动或链接效果。按住返回源窗口可继续排序，Esc 或外部取消不提交内部排序。接收效果取决于目标程序支持的格式。文件路径在拖放期间被外部删除仍可能失效；不支持任意原生格式或虚拟文件流。
- 拖动会话统一处理内部松手、OLE 回源释放与取消，避免框架内部拖动状态被原生事件清理后丢失手势；同代次历史刷新在拖动期间合并延后。预览窗口隐藏复用，普通跟随使用帧信号，100ms 兜底用于无帧时的收尾；让位使用 prepaint 位移与实际绘制进度命中。左键按下时预取轻量载荷，图片 DIB 使用最多一个运行任务和一个排队任务的专用线程；目标同步索取尚未完成的 DIB 仍可能等待。若载荷尚未就绪就已出窗松手，会明确提示重试，不伪装投递成功。
- 默认加载 100 条，点击“加载更多”继续；GPUI Kit `VirtualList` 按记录实际高度只渲染可见行，并保留滚动、键盘定位和边缘拖动的原有行为。
- 设置窗口中的“外观”提供跟随系统、浅色和深色；保存成功后生效，重启恢复选择。设置存于同一 SQLite 数据库，手动主题不随系统通知改变；未知设置值回退为跟随系统。
- “外观”页的「背景材质」提供本机支持的无（默认）、毛玻璃、云母；「背景浓度」保留 40%/55%/72%/85% 四档，越高越不透明，只控制外壳染色，不改变控件透明度或系统模糊半径。实际无材质时隐藏浓度及说明，切换材质不清除原浓度；背景材质作用于主窗口和设置窗口，卡片、输入框、菜单及通知保留主题表面，透明预览/拖动层不参与材质分发。
- Windows 能力通过 `RtlGetVersion` 探测并缓存：build 22621 起提供全部三种材质，17763–22620 以兼容亚克力实现毛玻璃，更早或未知版本仅不透明。macOS 毛玻璃通过独立 NativeBlur 后端使用系统模糊；Linux 当前没有已验证的原生模糊接入，仅提供不透明。设置页只列出支持项，显示按能力解析的当前选项；保存偏好不受支持时显示持续降级说明，直到用户明确选择才改写偏好。
- `gpui_window_effect` 键和 opacity 字段保留；有效旧值 none/acrylic/mica_alt 分别迁移并写回 opaque/frosted/mica，浓度原样保留。合法 canonical 配置只读不重写，损坏配置不被默认值覆盖，读写错误仍返回错误。材质保存后仅在原生后端改变时重新应用原生效果；切换材质与浓度均不重配窗口样式或客户区。
- 主窗口使用 GPUI 透明标题栏窗口选项，但不绘制顶部标题栏或系统标题栏按钮；搜索框上方有 30 px 高的握柄区域，可按住居中的浅色短横或其左右空白处拖动窗口。顶部边缘由 Windows 优先处理缩放，不能当作拖动点；列表底部固定的 28 px 记录数量栏仍可拖动窗口，“返回顶部”按钮保持可点击。占一行的快捷键说明已移除；Esc 或托盘控制显隐。独立设置窗口继续使用 gpui-kit `TitleBar`。
- 独立设置窗口初始内容区为 1280×720（16:9），居中打开；最小内容区仍为 700×420。Windows 外框会使实际窗口矩形略大于内容区尺寸。
- 设置窗口的“记住窗口大小”默认开启：主窗口停止缩放 300 ms 后保存最后一次普通窗口的内容区逻辑尺寸，重启时恢复；关闭后清除已保存尺寸并停止写入，重新开启后保存当前普通窗口尺寸。最大化和全屏状态不会覆盖普通尺寸；保存值缺失、损坏或超出 400×520 至 4096×2160 时回退到 420×640 默认尺寸。设置窗口可选择唤出位置：默认跟随光标，优先出现在光标右下方，水平空间不足时翻转到左侧；也可在光标所在显示器工作区居中，或在当前会话保持上次位置。前两种模式在启动及托盘、快捷键唤出时将窗口限制在光标所在显示器的工作区内，最大化或全屏时不移动。模式保存在 SQLite；窗口坐标不跨重启持久化，避免显示器变化后落到屏幕外。窗口尺寸记忆开关、已保存尺寸和定位模式随 GPUI ZIP 备份导出和恢复。

- 设置窗口的“隐藏时重置搜索、筛选和滚动”默认关闭。开启后，主窗口从关闭、Esc、快捷键、托盘或外部点击隐藏时，会清空搜索、回到全部记录和默认分组，并将列表滚动到顶部。无论开关状态，隐藏时都会退出未提交的批量选择；批量操作或粘贴请求正在处理时暂不隐藏窗口。预览文本正在编辑或保存时保留预览，避免丢失未保存内容。该设置随 GPUI ZIP 备份导出和恢复。
- 设置窗口的“唤出时清空搜索”默认开启，主窗口从托盘、快捷键或重复启动唤回时清空已有搜索并刷新当前分类/分组结果；“唤出时聚焦搜索”默认关闭，开启后启动显示及每次唤出时将键盘焦点放到搜索框。两项设置保存在 SQLite，并随 GPUI ZIP 备份导出和恢复。
- 主窗口搜索框独占一行，不再提供旁侧多选按钮，左右内容边距各 12 px；搜索框为 40 px 高，下方分类标签与 GPUI Kit 分组 Select 同行且为 32 px 高，四项等宽、分段四周各4px留白。清理当前组历史、置顶窗口和设置固定显示在托盘菜单，置顶项显示勾选状态；旧版保存的操作入口显隐和顺序配置不再生效。
- 设置窗口的“列表显示”可隐藏分类筛选栏（当前使用分类或收藏筛选时回到全部记录；浏览自定义分组时保留当前分组，并停止分类左右键切换），或在紧凑、标准、宽松三档卡片密度间切换；卡片预览行数默认为 2 行，可设置为 1 至 10 行，已有保存值保持不变；时间、字符数、大小和来源应用信息可分别显示或隐藏；显示时间可选绝对或相对格式。剪贴板变化时优先按剪贴板所有者识别来源进程，失败时回退到前台窗口；无法读取进程信息时不显示来源。识别到的可执行文件图标在后台提取并缓存为 PNG，卡片可按名称、图标或两者显示，提取失败时回退为名称；被记录引用的图标随 GPUI 备份导出和恢复。文本卡片高度随密度和预览行数变化，图片卡片使用单独行高及居中大缩略图；虚拟列表按实际行高布局，拖拽反馈距离同步更新；显示设置持久化并随备份恢复。
- 托盘置顶项使用 Windows topmost 窗口层级；开启后受控粘贴时窗口保持可见但键盘焦点仍交回目标应用。未置顶时可在“窗口行为”中选择粘贴后是否隐藏，默认隐藏；选择保持可见时仍将键盘焦点交给目标窗口。还可控制粘贴后是否将该条普通记录移到所在列表首位，默认开启；已置顶记录不改变顺序，合并粘贴不触发单条排序。仅在向原窗口成功发送粘贴快捷键后调整顺序。窗口可见且未置顶时，点击应用外的窗口或桌面会隐藏历史窗口到托盘；应用自己的悬停浮窗及设置窗口不触发隐藏，设置窗口打开或粘贴请求处理中也不自动隐藏。监听通过 Windows 鼠标钩子发送有界的点击事件，仅在主窗口可见时转发；不保存点击位置。置顶仅作用于当前运行会话，关闭应用后不保留。
- 点击历史列表内部空白不再隐藏主窗口或重置浏览状态；卡片点击继续选择或执行卡片操作。窗口外点击仍按既有置顶和操作状态处理，全局唤出快捷键仍可主动切换主窗口显隐。设置窗口关闭后，托盘、全局快捷键与窗口外点击继续监听主窗口。
- 关闭窗口后隐藏到系统托盘，左键托盘图标和全局快捷键可切换窗口显隐，最小化时会恢复；右键菜单“打开”始终显示并聚焦窗口，粘贴请求处理中暂不隐藏。右键菜单“退出”结束后台监听。在设置窗口中，“唤出”支持输入或录制 Ctrl/Alt/Shift/Win 与受支持按键的组合（新用户默认 `Alt+C`，已保存的快捷键保持不变），也可关闭，配置保存在 GPUI 设置中并兼容旧预设。组合键被占用时提示并恢复原快捷键，托盘入口仍可用；托盘初始化失败时关闭窗口正常退出。用全局快捷键从目标应用唤出后，卡片与预览上的“粘贴”按钮可先复制，再隐藏历史窗口并尝试向原窗口发送设置中选择的 Ctrl+V 或 Shift+Insert；离开历史窗口会清除原目标和未完成的粘贴请求，再直接点回时需从目标应用重新按热键唤出。托盘唤出或目标窗口失效时仅能手动复制。修饰键按住时异步等待最多 2 秒，每 20ms 核对目标身份、前台和剪贴板序列，松开后才发送；超时、目标变化、序列变化或按键注入失败明确提示手动粘贴。新复制请求或重新唤出窗口会取消旧投递任务。普通文本、图片、文件及富文本均读回校验后才确认写入；底层部分写入失败不承诺恢复旧剪贴板。Windows 无法从按键注入返回值确认目标应用已经完成粘贴，因此成功提示仅表示已发送快捷键。粘贴按键可选 Ctrl+V（默认）或 Shift+Insert，配置保存在 SQLite 并随 GPUI 备份恢复；当前不支持任意按键组合录制。
- 选择 `Alt+C` 唤出时，可以按住 Alt 不放，反复按下并松开 C，依次唤出和隐藏主窗口；C 持续按住不会自动连发。Windows 上主窗口唤出且 Alt 仍被按住时直接聚焦窗口，避免 GPUI 默认激活过程注入 Alt 松开事件；未按住 Alt 时继续使用原有窗口激活路径。
- 设置窗口中的“开机启动”默认关闭；用户开启后在当前用户 Run 键写入与该数据目录对应的独立项，关闭后删除。启动命令使用当前可执行文件、该数据目录和 `--start-hidden`；开机启动时窗口不弹出，可由托盘或快捷键唤回，托盘初始化失败则显示窗口。移动可执行文件后需要在新位置重新开启，才能更新启动命令。
- Windows MSVC 版的 GPUI 主线程预留 8 MiB 栈空间；设置窗口元素树在系统默认 1 MiB 预留量下会触发栈溢出。该数值是虚拟地址预留，物理内存随实际使用提交；构建脚本仅对本应用的 Windows MSVC 可执行文件设置链接参数。隔离窗口打开设置和编辑快捷键的过程见 [快捷键界面验收](evidence/windows-quick-paste-shortcuts-2026-09-25.md)。

## 默认诊断日志与双屏定位重入

默认启用 `%LOCALAPPDATA%\ElegantClipboardLogs` 下的会话日志，目录独立于数据库和导入目标。`application.log` 同步写入、4 MiB 轮转、最多三份备份；仅清理符合生成规则且未被进程持锁的旧会话，保留最近五个非活动会话。Rust panic 绕过普通日志互斥锁，独立写入并同步 `panic.log`，包含时间、线程、代码位置及强制堆栈。普通事件与 panic 文件各有 1 MiB 上限和截断标记；panic 消息另限 64 KiB，为堆栈留出空间。原始剪贴板正文、搜索词、图片像素和分组名不主动记录；异常字符串可能带本机路径。

在双显示器隔离验证中，日志记录了主屏 `(0,0,2560,1440)`、副屏 `(-1920,0,1920,1080)`、窗口 DPI 96、显示器 ID 切换，以及预览计划/实际几何和缩放前后的原生调用。日志也暴露了副屏预览计划位置与实际创建位置不一致及已有资源加载错误；这些记录不等同于本轮已修复所有多屏问题。

随后实际原生冒烟捕获到 `gpui-pre/src/app/async_context.rs:178` 的 `RefCell already borrowed` panic，堆栈为 `ClipboardView::new → position_window → SetWindowPos → handle_move_msg → set_display → AsyncApp::update`。当原生移动同步回调跨屏变化时，GPUI App 仍被初始化过程借用。现将 Windows 定位拆为借用内计算、前台异步任务中无 App/Window/Entity 借用地执行；同一入口覆盖启动和再次显示。没有捕获/吞掉该 panic，也没有禁用显示器回调。

修复后 Debug 和最终 Release 均在鼠标位于主屏及负坐标副屏的隔离启动中正常退出，退出码 0，正常关闭记录落盘。诊断回归覆盖轮转上限、活动会话保留、无关目录保护、并发线程/进程记录隔离、默认隐私过滤、持有普通日志锁时 panic 写盘，以及 hook 后立即 abort 的子进程。`just check`、417 项测试（2 项原有忽略）与 Release 构建通过。真实 panic 的本地证据保存在忽略目录 `target/qa/captured-cross-display-panic/`。

Windows fail-fast、进程强杀和断电不保证触发 Rust panic hook；没有 `panic.log` 时仍应结合 `application.log` 的最后操作与 Windows Application 事件。用户原始 `0xc0000409 / ucrtbase.dll` 记录与本轮捕获路径有关联可能，但不能仅凭异常码认定所有闪退根因相同。

## QcClip 预览样式与动效对齐

当前预览采用覆盖来源显示器工作区的透明穿透绘制层，不再使用“缩放原生小窗口＋单独连接窗口”的结构。窗口隐藏创建，明确选择显示器，在 GPUI 借用之外完成物理客户区定位、无框/不激活/穿透配置后显示；Windows 命中测试返回 `HTTRANSPARENT`。工作区原点保留负坐标，渲染时才转为显示器局部逻辑坐标。

图片、文本/HTML、文件内容、备注、连接线和信息标签绘制在同一层。图片初始适配 480×480；文本按实际字形尺寸测量，HTML 按实际 TextView 布局测量，避免短内容固定撑成大窗口。表面圆角跟随内部主题半径，图片与备注使用对应内圆角，浮层阴影使用共享token，非图片带1px细边框；连接线为1.5px、65%不透明度的主题色贝塞尔曲线，端点为8px、14%不透明度光晕包围4px实心点。控制点不超过两端朝向间距的一半，避免短距离曲线鼓包或回折。信息标签使用官方Tag，按可用区域换行，优先放在预览上方，不遮挡主窗口或预览内容。比例根据原图物理像素和实际显示尺寸计算；数据格式只展示已有的真实存储信息，不伪造原始CF_DIB。

材质更新只分发给应用 Root 窗口；无 Root 的预览及拖动绘制层不参与，避免延迟到达的设置保存回执给整个显示器绘制不透明/模糊背板。

展开和透明度分别使用 190ms ease-out-quint：侧边从零宽度和来源卡片高度展开，上下方向从零高度展开；内部内容保持目标尺寸，外层裁切动画。内容、连接线、端点和信息共用透明度动画，连接线与信息跟随测量后的表面边界，避免端点突然出现。非激活窗口关闭默认 30fps 限制；减少动态效果时跳过动画。Ctrl＋滚轮缩放不重播入场动画，默认灵敏度每步调整 48px 基准大小；文本通过同一来源卡片手势滚动。鼠标离开来源时关闭，原生位置核对仅在预览打开期间工作。保留既有悬停延时与灵敏度偏好。

禁用剪贴板采集的合成数据原生验证覆盖主屏 `(0,0,2560,1392)` 与副屏 `(-1920,0,1920,1032)` 工作区：预览显示与 Ctrl＋滚轮缩放期间原生窗口范围不变，图片比例标签由 63% 更新至 81%；离开来源后关闭。短文本紧凑显示，50 行文本经来源 Ctrl＋滚轮滚动后显示后段内容，HTML 的标题/粗体正文按实际内容收缩。动画抓帧观察到空/裁切展开阶段和完整表面，帧位于打开后约 39/110/188ms（抓帧时序不是帧率测量）。本地截图位于 `target/qa/overlay-*.png`。

两个实测显示器均为 96 DPI；不同 DPI 的真实组合以及 macOS/Linux 原生视觉效果未实测。

## 圆角关闭与跟随系统

圆角偏好改用 `CornerRadiusPreference::System / Fixed(u8)`，不是特殊数值哨兵。`gpui_corner_radius` 的 `system` 表示跟随系统，其他数字仍按原格式存储；旧8迁移并写回system，非法值不被覆盖，迁移失败返回错误。新用户默认跟随系统；已保存的4px及其他合法值不被新默认覆盖。原12px等其他合法旧值保留：界面不误选「跟随系统」，而是提示当前旧值，直到用户选择新选项。

圆角偏好只投影到内部组件的主题半径，不调用DWM或其他原生窗口圆角接口。跟随系统时，内部控件使用当前主题配置的默认半径；配置未指定时恢复应用覆盖之前捕获的Kit默认值，不会沿用上次选择的16px。关闭将内部组件半径设为0。启动、保存回执和切换主题均不再修改原生窗口圆角；原生圆角模块和专用能力检测已移除。预览内部表面、图片与备注圆角也使用主题半径，透明原生绘制层不变。
